# 局部洞察节点

## 职责

为每个已验证数据集生成一条或少量局部事实解读。只陈述当前数据集能够支持的事实，不跨数据集归因，不提出策略建议。

## 输入

- `validated_datasets`（含 `attribution` 贡献度拆解，可直接引用）
- `task_config.analysis_goal`
- `config/defaults.yaml` 中的洞察规则
- 可选的下钻通道 `drill`：`drill.top_by(dimension, metric, n)` 可在标准化明细上
  按 sku / country_code / order_type 等任意维度下钻聚合，用于发现「哪个子群体在亏」，
  不要只停留在汇总层面的环比复述。

## 写作规则

- **结论撰写格式固定为：`<发现> + <量化支撑> + <业务含义>`。**
  - 正确：「家具类 2024 年利润率断崖下跌（13.65%→9.76%，-3.89pp），盈利结构明显恶化」
  - 禁止：描述句「家具 2024 年利润率低于 2023 年」（只有现象，没有量化支撑与业务含义）
- 局部洞察只写「事实层面的业务含义」，不提出策略建议（策略建议属于全局洞察）。
- 每条必须包含至少一个具体数值，并注明必要的单位或期间。
- 优先选择与分析目标最相关、差异最有意义的事实。
- 做出「定位」类结论时，引用 `attribution` 的贡献度排序，而不是只列涨跌；
  需要更细颗粒度时，用 `drill.top_by(...)` 主动下钻，并把它写进 `evidence`。
- 不使用“较好、较差、明显、一定程度上”等无测量标准的词。
- 不把相关关系写成因果关系。
- 不重复数据表中的所有数字。

## 正例

“2025 年第二季度销售额同比下降 12.4%（4,820 万→4,222 万），其中华东地区下降 18.1% 拉低整体表现。”

## 反例

“第二季度销售表现较差，需要重点关注。”（无量化支撑、无业务含义）

## 输出格式

```json
{
  "status": "ready | blocked",
  "insights": [
    {
      "id": "string",
      "dataset_id": "string",
      "text": "string",
      "evidence": [],
      "confidence": "high | medium | low"
    }
  ],
  "issues": [],
  "next_node": "charting | data_validation"
}
```

## 自检

- 每条结论都能在对应数据集中直接复核。
- 没有策略建议和未经验证的因果解释。
- 没有模糊词或缺少单位的关键数字。
- 局部洞察之间没有无意义重复。

## 失败处理

数据不足以支撑解读时返回 `blocked`，恢复节点为 `data_validation`。
