# 架构说明

## 三层配置

### 静态 Skill 规则

稳定的执行规则放在 `SKILL.md`、`config/defaults.yaml` 和节点提示词模板中：

- 节点职责和交接关系
- 输出契约和字段命名
- 校验和恢复行为
- 图表选择原则
- 证据和洞察写作规则

### 领域配置

可复用的领域知识放在领域配置中，例如 `config/domains/sales.yaml`：

- 常见分析维度和指标
- 指标定义和单位
- 已知的数据关系
- 领域特有的问题和风险信号
- 推荐分析，而不是强制分析

### 运行时任务配置

分析师提供或确认当前任务：

- 分析目标
- 数据源和字段映射
- 时间范围和时间粒度
- 分析维度、指标和过滤条件
- 对比基准或目标值
- 使用对象和输出格式

缺失或含义不明确的业务条件，必须在制定分析计划前澄清。

## 节点契约模板

每个节点提示词都应包含：

1. 单一职责。
2. 明确的输入字段和假设。
3. 针对输入执行的任务步骤。
4. 来自 Skill 或领域配置的固定约束。
5. 可机器读取的输出 Schema。
6. 具有可测量标准的自检项。
7. 失败状态和恢复节点。

对于洞察等主观输出，使用“规则 + 正例 + 反例”。对于计算和校验，尽可能使用确定性实现。

每个节点的正式输出契约位于 `schemas/`，并由 `workflow/pipeline.yaml` 的 `output_schema` 字段绑定。提示词中的 JSON 示例用于帮助模型理解，不替代正式 Schema。

## 确定性校验

- 使用 `scripts/validate_artifact.py <schema> <instance>` 校验节点输出。
- 使用 `scripts/validate_pipeline.py` 检查节点 ID、失败路由、提示词路径和 Schema 路径。
- 使用 `scripts/validate_run.py <manifest.json>` 检查计划范围、节点覆盖、跨节点 ID 引用以及交付物是否真实存在。
- 结构校验通过后仍需执行领域校验，例如指标勾稽、单位一致性和结论证据核对。

## 数据血缘

每个输出产物都应保留足够的元数据，以回答：

- 哪份任务配置生成了它；
- 使用了哪些源字段和过滤条件；
- 哪个节点创建或修改了它；
- 哪些校验通过或失败；
- 引入了哪些假设。
